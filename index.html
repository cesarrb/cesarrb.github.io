W1 · Retrieval-augmented generation (RAG)Public repo

Knowledge assistant: answers from recorded talks, with citations that are checked

A private chat assistant over transcripts and documents. It searches by keyword and by meaning, answers only from what it found, and removes any citation that points to a passage it never retrieved.

237 hof lectures turned into an EN/ES guide (180 videos)
6,398passages indexed for one expert corpus: blog, 12 interviews, ~1,550 posts
3interchangeable model backends: Ollama, LM Studio, Claude
9automated tests, including the citation check that drops invented sources
  1. Transcripts and docsdated, with source URL
  2. Chunk~250 words; speaker turns only
  3. Hybrid searchBM25 + vectors, fused (RRF)
  4. Grounded answer"no material" if not covered
  5. Citation checkdrop unretrieved ids
  6. Reader verifiesclick citation → source
AI stepHuman step

Problem

Expertise lives in long recorded talks and interviews. Nobody has time to watch 200+ hours to find one answer, and generic chatbots cite sources they never read.

Tools

Python and SQLite full-text search (FTS5), Ollama embeddings, NumPy, local Qwen models or the Claude Code CLI, a single-file web UI. No framework.

What I built

  • Keyword (BM25) and vector retrieval combined with reciprocal rank fusion (RRF)
  • A cap per document so one long source cannot crowd out the rest
  • A video pipeline: subtitles and key slides → summaries with links to the exact minute

Guardrails

  • Answers only from retrieved sources; says so when the sources do not cover the question
  • Interviewer questions are never attributed to the guest
  • Runs fully local by default, so documents stay on the machine

Governed data, ready for AI: catalogue, lineage and contracts kept as code

AI is only as reliable as the data behind it. This project governs a synthetic SAP-style supply chain from ERP tables to the KPI dashboard, using OpenMetadata, dbt and Metabase, all checked automatically on every change.

Problem

Teams want AI on top of ERP data, but nobody can say where a KPI comes from, who owns it, which columns hold personal data or whether today's numbers passed their checks.

Tools

OpenMetadata 2.0.7, dbt, Postgres, Metabase, Docker, GitHub Actions. Governance rules written in YAML files.

What I built

  • Lineage from raw tables to each dashboard chart, derived automatically
  • 13 business glossary terms (OTIF, days of inventory, safety stock…) linked to the column that computes each KPI
  • An access policy and a governance scorecard

Guardrails

  • Personal-data tags confirmed by a human data steward
  • dbt refuses to build a certified table whose schema drifts
  • Every pull request rebuilds the warehouse and blocks on failed tests

How I run an AI rollout

The same five steps in every workflow

  1. Step 1Pick a painful taskFrequent, slow and easy to check. Time it before changing anything.
  2. Step 2Write the rules firstWhat the model may use, what it must never do, and where a human signs off.
  3. Step 3Build the smallest versionLocal or approved tools, real inputs, one owner.
  4. Step 4MeasureVolume handled, errors caught, minutes saved, and whether people keep using it.
  5. Step 5Hand it overShort guide, prompt library and office hours, so the team runs it without me.
